# وابستگی‌های باقی‌مانده

تا این مرحله، کد محلی، رابط، آداپتور مبتنی بر قرارداد API، آزمون‌ها و مستندات آماده‌اند. نتایج در RESULTS.md به نوع واقعی/نمایشی تفکیک شده‌اند.

| بند | قدم بعدی و وابستگی |
|---|---|
| ۱۹: BTCPay/regtest واقعی | محیط دارای Docker یا استقرار رسمی معادل فراهم شود. Docker در این دستگاه پیدا نشد؛ اجرای موفق هسته یا نود ادعا نشده است. راهنمای INTEGRATION.md آماده است. |
| ۲۰: ولت testnet | پس از هستهٔ واقعی، صاحب ولت آزمایشی با دارایی آزمایشی مسیر را اجرا کند. QR ساختگی و آزمون mock جای این مرحله نیستند. |
| ۲۱: سه آزمایش‌کننده | سه شخص واقعی، بدون راهنمایی سازنده، نمونه را اجرا و مراحل مبهم را گزارش کنند. متن دعوت آماده است؛ هنوز بازخوردی دریافت نشده است. |
| ۲۲: پنج مصاحبه | پنج سازنده دربارهٔ مشکل، راه‌حل فعلی و تمایل به پرداخت جواب واقعی بدهند. سؤال‌ها آماده‌اند؛ مشتری یا امتیاز فرضی ساخته نشده است. |
| ۲۳: میزبان و بودجه | اقامت و نوع فعالیت با شرایط میزبان/RPC بررسی و هزینهٔ واقعی انتخاب‌شده ثبت شود. طرح مقایسهٔ هزینه آماده است؛ هیچ سرویس پولی خریده نشده است. |
| ۲۴: پایلوت واقعی | نتایج هسته/ولت واقعی، امنیت، backup، شرایط حقوقی/سرویسی و بودجه لازم است. برنامهٔ فعلی پول واقعی دریافت نمی‌کند. |
| ۲۵: چندکاربره/شبکهٔ دوم | نیاز مشتری و ظرفیت نگهداری اثبات شود؛ سپس مالکیت صفحات، جداسازی فروشگاه‌ها و شبکهٔ منتخب جداگانه پیاده‌سازی و آزمون شوند. |
| ۲۶: درآمد | ارائهٔ پیشنهاد واقعی خدمات نرم‌افزار و پاسخ/پرداخت واقعی مشتری لازم است. عدد درآمد یا سود تضمینی نداریم. |

## دعوت آماده — ارسال نشده

I'm testing Creator Rail, a local Persian/English support-page prototype with synthetic payment fixtures. No real funds or wallet secrets are involved. Could you try the setup guide without my help and tell me where you got stuck, what was useful and what was missing? Please use only the demo; real processor integration is a separate milestone.

دعوت جدید برای این پروژه بدون مشخص‌شدن مخاطب و اجازهٔ ارسال منتشر نشده است. دعوت قبلی Maze Signal مربوط به پروژهٔ دیگری بود.

## سؤال‌های مصاحبه

۱. اکنون حمایت یا هزینهٔ خدمات را چگونه دریافت می‌کنی و بزرگ‌ترین مشکل واقعی چیست؟

۲. آیا خودمیزبانی را می‌توانی نگهداری کنی؟ اگر نه، چه کمکی نیاز داری؟

۳. چه قابلیت مشخصی در ابزار فعلی تو کم است؟

۴. برای راه‌اندازی، سفارشی‌سازی یا پشتیبانی چه بودجه‌ای داری؟ پاسخ فرضی را فروش حساب نکنیم.

۵. چه چیزی باعث می‌شود این نمونه را واقعاً دوباره استفاده کنی؟

## هزینه‌های لازم برای مقایسهٔ میزبان

دامنه، سرور/ذخیره، پشتیبان‌گیری، RPC یا نود، ترافیک، امنیت و زمان پشتیبانی؛ هزینهٔ نرم‌افزار متن‌باز با هزینهٔ اجرای سرویس یکی نیست. قیمت قطعی پس از انتخاب سرویس واجد شرایط ثبت می‌شود. GitHub Pages میزبان کسب‌وکار پرداخت یا SaaS تجاری نیست.
